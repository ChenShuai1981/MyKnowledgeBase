# 技术内容深度分析技能

## 使用场景

对已采集的技术内容（如 GitHub Trending 采集文件）进行深度分析，生成结构化摘要、评分和趋势发现，为知识沉淀提供高质量输出。

## 执行步骤

### 第 1 步：读取最新采集文件

定位并读取 `knowledge/raw/` 目录下当天最新的采集文件：

```bash
ls -t knowledge/raw/github-trending-*.json | head -1
```

读取 JSON 文件内容并解析 `items` 数组，获取待分析的仓库列表。

注意事项：
- 仅处理 `knowledge/raw/` 目录下的原始采集文件，不处理历史文件或已分析文件
- 若当天无采集文件，降级读取最近 7 天内最新的文件
- 文件读取失败时记录 ERROR 并终止执行

### 第 2 步：逐条深度分析

对每个项目进行结构化分析，输出以下字段：

#### 2.1 摘要（≤50 字）

将原始描述压缩为 50 字以内的精炼摘要，突出核心功能：

```
项目名：核心功能一句话描述
```

#### 2.2 技术亮点（2-3 个，用事实说话）

从仓库的 README、Stars 增长趋势、社区讨论中提取 2-3 个具体技术亮点：

- **亮点 1**：[具体说明，如使用了某项创新技术/架构/算法]
- **亮点 2**：[具体说明，如解决了某具体痛点问题]
- **亮点 3**（可选）：[具体说明，如性能指标/效率提升数据]

要求：必须引用具体事实（代码实现、测试数据、官方声称），避免模糊描述。

#### 2.3 评分（1-10，附理由）

按照以下评分标准进行打分：

| 分数段 | 含义 | 说明 |
|--------|------|------|
| **9-10** | 改变格局 | 具备突破性创新，可能重塑技术方向或行业格局 |
| **7-8** | 直接有帮助 | 问题解决效果显著，可直接应用于实际工作 |
| **5-6** | 值得了解 | 有一定价值，可作为技术储备或了解趋势 |
| **1-4** | 可略过 | 创新不足或应用场景有限，了解即可 |

附理由说明评分依据（必填），格式：

```
评分：{分数}
理由：{1-2 句话说明评分依据}
```

#### 2.4 标签建议

根据项目特性建议 2-4 个标签：

- 技术类别标签（如：`llm`, `agent`, `rag`, `nlp`, `computer-vision`）
- 应用场景标签（如：` productivity`, `dev-tools`, `data-analysis`）
- 创新程度标签（如：`trending`, `fast-growing`, `solid-quality`）

### 第 3 步：趋势发现

在分析完所有项目后，进行全局趋势发现：

#### 3.1 共同主题

统计 `items[].topics` 出现频率，识别当前最热门的技术主题：

```
主题 1：{主题名} - {出现次数} 个项目涉及
主题 2：{主题名} - {出现次数} 个项目涉及
...
```

#### 3.2 新概念

识别在采集数据中首次出现或出现频率快速增长的概念/技术：

```
新概念 1：{概念名} - {解释其在当前趋势中的意义}
新概念 2：{概念名} - {解释其在当前趋势中的意义}
...
```

要求：仅标注明确的趋势信号，避免过度解读。

### 第 4 步：输出分析结果 JSON

将分析结果写入 `knowledge/analyzed/tech-summary-YYYY-MM-DD.json`（日期为当天日期），JSON 结构如下：

```json
{
  "source": "github-trending",
  "skill": "tech-summary",
  "collected_at": "YYYY-MM-DDThh:mm:ss",
  "analysis_date": "YYYY-MM-DD",
  "total_items": 15,
  "score_distribution": {
    "9-10": 1,
    "7-8": 6,
    "5-6": 7,
    "1-4": 1
  },
  "trend_findings": {
    "common_topics": [
      {
        "topic": "llm",
        "count": 8
      },
      {
        "topic": "agent",
        "count": 5
      }
    ],
    "new_concepts": [
      {
        "concept": "概念名",
        "description": "概念解释"
      }
    ]
  },
  "items": [
    {
      "name": "owner/repo",
      "url": "https://github.com/owner/repo",
      "summary": "精炼摘要（≤50字）",
      "tech_highlights": [
        "亮点 1：具体事实描述",
        "亮点 2：具体事实描述"
      ],
      "score": 8,
      "score_reason": "评分理由",
      "tags": ["llm", "agent", "dev-tools"]
    }
  ]
}
```

## 注意事项

- **评分约束**：15 个项目中 9-10 分不超过 2 个，确保高质量筛选标准；若超过则按评分降序仅保留前 2 个并标注
- **去重分析**：同一仓库在不同采集文件中出现时应跳过分析（已在历史分析中覆盖）
- **字段完整性**：所有 `items` 中的字段均为必填，缺失字段应标记为 `"N/A"` 并记录 WARNING
- **趋势发现**：若无明显趋势发现，`trend_findings` 中的字段可为空数组，但不应缺失
- **输出目录**：`knowledge/analyzed/` 目录需提前创建，如不存在则自动创建

## 输出格式

最终产物为单个 JSON 文件，路径为：

```
knowledge/analyzed/tech-summary-YYYY-MM-DD.json
```

文件编码为 UTF-8，缩进 2 空格，日期格式严格使用 `YYYY-MM-DD`。
